# KB-CLI 0.2.0

发布日期：2026-11-14。最低 Rust 版本为 **1.89**。本版本集中修复知识库声明、Agent 记忆、配置、并发写入和安装发布流程，并包含需要调整调用脚本的行为变化。

## 安装与升级

安装包：

- Windows x86_64：`kb-cli-0.2.0-windows-x86_64.zip`，解压后运行 `install.cmd`。
- Linux x86_64 GNU：`kb-cli-0.2.0-linux-x86_64.tar.gz`，解压后运行 `bash install.sh`。

安装后运行 `kb --version`，应显示 `kb 0.2.0`；再运行 `kb env --doctor` 检查实际配置路径。详细操作见[安装与打包指南](https://github.com/jlu005807/Kb-cli/blob/v0.2.0/docs/cli/install-and-package.md)。

升级现有知识库时，先保留 `kb.md`、`.kb/` 和全局配置的备份，再安装新版本，在知识库目录执行 `kb check`、`kb update`。SQLite 数据库自动迁移至当前 schema v5；需要回退程序版本时使用升级前备份。

## 兼容性变化

- **移除全局 `--config`**，用 `KB_GLOBAL_CONFIG` 指定全局配置文件。旧 `E2008` 编号保留，不再使用。
- **移除 `kb update --yes`**。该参数原本没有作用，现在会被参数解析拒绝。
- `kb update` 默认保留缺失路径在 `kb.md` 中的声明，仅移除登记与索引；需要删声明时显式传 `--prune`。输出新增 `missing_declarations`，它不影响 `--strict`。
- 全局配置按非空 `KB_GLOBAL_CONFIG`、已存在的安装目录 `config.json`、用户目录 `~/.kb-cli/config.json` 依次选择；可执行文件在 `bin/` 下时检查父目录。新安装可能开始使用用户目录配置。
- `quiet`、`verbose`、`no_color` 现在按字段从 flags、环境、项目、全局配置合并。已有 `KB_QUIET`、`KB_VERBOSE` 等设置会真实生效，显式 false/0 也会覆盖较低优先级。
- 显式非法存储配置会报错，不再静默切换 FS。记忆命令、ask 存储故障及 MCP 存储工具使用 `E1004`；writer lock 冲突使用 `E3004`，Ctrl+C 退出码为 130。
- `kb mv` / `kb path` 改写真实的 `kb.md` 声明，后续运行 `kb update` 收敛索引。CLI 不再对仅存在于旧工作集中的条目做无效改名。
- `ask --answer` 的工具循环改用独立 `ask_loop_max_rounds` / `KB_LLM_ASK_LOOP_MAX_ROUNDS`，默认 8，范围 4–12；`agent_loop_max_rounds` 只管理派生层编译。

## 主要修复

- 陈旧 chunk 校验 UTF-8 边界和内容签名，回退 preview 并返回 stale 状态；单次 MCP 工具 panic 不再终止服务。修正 Windows 盘符 chunk id 解析。
- `kb.md` 支持 UTF-8 BOM，改写保留 BOM、行尾和尾部换行；修正分类插入位置。混合行尾按首次出现的风格统一。
- copy 模式不覆盖已存在的 raw 文件，包括尚未登记的文件；保留源权限，源打开失败不残留新目标。
- `kb init` 对损坏或不支持字段结构的全局配置报告注册失败，保留原文件；本地初始化仍可完成。BOM 配置可被正常读取。
- JSONL 损坏或截断的 UTF-8 行不再阻断其他有效 episode；查询按时间和 id 排序后选择最近 N 条。
- consolidate 防止不同 topic 文件名碰撞；已有匹配 topic 的文件继续复用，新文件仅在需要时使用哈希后缀。
- SQLite 完整保留知识条目的 confidence、来源、时间和 provenance 等字段。
- 写命令使用操作系统单写者锁；原子写和中断恢复避免留下半写入声明。被打断的 update 可再次执行以收敛派生层。
- Windows 安装器输出无 BOM UTF-8，升级保留已有配置字段。Linux 卸载保留 rc 符号链接和权限，写失败不截断原文件；自定义目录中的 shell 特殊字符按字面转义。

## 验证与当前边界

发布前执行 Windows/Linux workspace Clippy、Rust 测试、文档 fixture 和实际归档安装验收；包内 CLI 完成 `init → add → update → ask` 及 MCP initialize/tools/list/ping，卸载保留配置和无关文件。污染模型环境变量时，验收通过本地 HTTP stub 检查没有模型请求。

本地 0.2.0 构建验收已通过：Windows 354 项、Linux Rust 1.89 352 项 Rust 测试，Clippy 无警告；20 组文档 fixture 匹配。Linux 的 4 项 Node 测试通过，Windows 执行其中 3 项，Bash 工作流测试由 Linux 验证。

Release 工作流先创建 draft，只有两平台构建和安装验收全部成功后才公开。

SQLite 后端下，`ask --answer` 的部分 toolbox 以及 MCP `read_summary` / `read_neighbors` 仍读取 FS 派生文件布局；数据缺失时会带 warning。历史错分类的声明不会自动迁移，可用 `kb check` / `kb list --tree` 检查并手动调整。
